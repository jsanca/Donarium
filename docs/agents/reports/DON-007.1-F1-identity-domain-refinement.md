# DON-007.1-F1 — Identity Domain Refinement

**Status:** COMPLETE
**Owner:** Deep Pro
**Parent:** DON-007.1 — Identity Domain

## Summary

Refined the Identity domain model across 7 dimensions before introducing
persistence. Every relationship uses typed IDs, roles are split by context,
PasswordHash is a dedicated type, PasswordPolicy is immutable, constructors
enforce invariants, and Membership identity is explicitly documented.

## Changes by dimension

### 1. Strongly typed IDs

| Type | Before | After |
|---|---|---|
| Credential.UserID | `uuid.UUID` | `UserID` |
| Organization.CreatedBy | `uuid.UUID` | `UserID` |
| Membership.UserID | `uuid.UUID` | `UserID` |
| Membership.OrganizationID | `uuid.UUID` | `OrganizationID` |
| Repository method params | `uuid.UUID` | `UserID` / `OrganizationID` |
| SetupResult fields | `uuid.UUID` | `UserID` / `OrganizationID` |

All ID types gain `IsZero()` for nil checks.

### 2. Role separation

- **PlatformRole** — `super_admin` (cross-organization access, future use)
- **OrganizationRole** — `owner` only (the one role needed for initial setup)

Removed: manager, tenant, maintenance_staff — these belong to later slices
or other domains (tenant → leasing).

### 3. PasswordHash type

```go
type PasswordHash string
```

Credential now uses `PasswordHash` instead of raw `string`. Prevents
accidental mixing of plaintext and hashed values.

### 4. Membership identity

Explicit composite key `(UserID, OrganizationID)`. No surrogate key.
A user can have only one role per organization. Documented in the struct
as the implicit PK.

### 5. PasswordPolicy immutability

All fields unexported (`minLength`, `requireUpper`, etc.). Only
`DefaultPasswordPolicy()` creates valid instances. No accidental
configuration of broken policies.

### 6. Constructor validation

| Constructor | Validates |
|---|---|
| `NewUser` | email not empty, displayName not empty |
| `NewCredential` | userID not zero, passwordHash not empty |
| `NewOrganization` | name not empty, slug not empty, slug matches `^[a-z0-9]+(-[a-z0-9]+)*$`, createdBy not zero |
| `NewMembership` | userID not zero, orgID not zero, valid OrganizationRole |

All constructors return `(T, error)`.

### 7. Creation vs rehydration

Constructors generate IDs and timestamps for new objects. Exported struct
fields allow persistence layers to hydrate from database rows directly.
No separate "from persistence" factory needed — this is the standard Go
pattern.
