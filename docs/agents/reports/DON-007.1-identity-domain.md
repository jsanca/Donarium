# DON-007.1 — Identity Domain

**Status:** COMPLETE
**Owner:** Deep Pro
**Parent:** DON-007 — Initial Owner Setup (Vertical Slice)

## Summary

Implemented the Identity domain layer with 5 entities (User, Credential,
Organization, Membership, Role), 1 value object (PasswordPolicy), 4 repository
interfaces, and 1 service interface. No PostgreSQL, no HTTP, no pgx, no
handlers. Pure domain code with constructors and validation logic.

## Domain Model

| Type | Kind | Description |
|---|---|---|
| User | Entity | Person who can authenticate, has email + display name |
| Credential | Entity | Password hash linked to a User |
| Organization | Aggregate Root | Workspace/tenant with name, slug, createdBy |
| Membership | Entity | User-to-Organization join with a Role |
| Role | Enum | owner, manager, tenant, maintenance_staff |
| PasswordPolicy | Value Object | MinLength, character requirements, Validate() |

## Interfaces

| Interface | Context |
|---|---|
| UserRepository | Create, FindByID, FindByEmail, ExistsByEmail |
| CredentialRepository | Create, FindByUserID |
| OrganizationRepository | Create, FindByID, FindBySlug, Exists |
| MembershipRepository | Create, FindByUserAndOrg |
| SetupService | Setup(req) → (result, error) |

## Tests

## Decisions

- **google/uuid for IDs.** Named ID types (UserID, OrganizationID, CredentialID)
  prevent passing the wrong UUID to the wrong method. All are `uuid.UUID` under
  the hood.
- **PasswordPolicy as value object.** Stateless, pure validation. No dependency
  on external libraries. Unicode-aware character classification.
- **Repository interfaces take context.Context.** Consistent with Go convention
  for cancellation and deadline propagation, even without implementations yet.
- **Constructor functions (NewUser, NewOrganization, etc.).** Set UUIDs and
  timestamps on creation. Callers don't need to handle ID generation.
- **Sentinel errors.** 11 domain errors using `errors.New`. Callers can use
  `errors.Is` for matching.
