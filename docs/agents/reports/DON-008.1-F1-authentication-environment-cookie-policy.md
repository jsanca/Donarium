# DON-008.1-F1 — Authentication Environment and Cookie Policy

**Status:** COMPLETE
**Owner:** Deep
**Role:** Implementation Engineer

## Summary

Resolved AAR-001 by introducing explicit environment configuration
(DONARIUM_ENV), secure signing key policy per environment, SESSION_TTL
validation with startup errors, and a dedicated `SessionCookieWriter`
abstraction extracted from `LoginHandler`.

## Environment Model

| Environment | Secure cookie | Signing key fallback | Dev key allowed |
|---|---|---|---|
| local | `Secure=false` | Yes (default dev key) | Yes |
| qa | `Secure=false` | Yes (default dev key) | Yes |
| staging | `Secure=true` | No | No |
| production | `Secure=true` | No | No |

Configured via `DONARIUM_ENV` env var (default: `local`). Unknown values
are rejected at startup.

## Signing Key Policy

- **local/qa**: Falls back to dev key if `SESSION_SIGNING_KEY` unset
- **staging/production**: `SESSION_SIGNING_KEY` required. Rejects dev key.
  Rejects keys shorter than 32 characters.
- Key never appears in logs.

## SESSION_TTL Validation

- Empty → default 24h
- Invalid format → startup error
- Zero or negative → startup error

## Cookie Abstraction

`SessionCookieWriter` interface extracted from `LoginHandler`:

```go
type SessionCookieWriter interface {
    Write(w http.ResponseWriter, token string)
    Clear(w http.ResponseWriter)
}
```

`CookieSessionHandler` implementation sets:
- `donarium_session`, `Path=/`, `HttpOnly`, `SameSite=Lax`
- `Secure` configured by environment (`cfg.IsProduction()`)
- `MaxAge` and `Expires` derived from `SESSION_TTL`

## Tradeoffs

- **`IsProduction()` includes staging**: Staging environments should have
  production-equivalent security. This is intentional.
- **Default TTL 24h**: Matches DON-008.1 default. Follow-up should define
  environment-specific TTL policies.
- **Secure=false for QA HTTP**: necessary since QA runs over HTTP. A reverse
  proxy with TLS termination would change this.
