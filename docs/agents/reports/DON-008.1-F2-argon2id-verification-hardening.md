# DON-008.1-F2 — Harden Argon2id Verification

**Status:** COMPLETE
**Owner:** Deep
**Role:** Security Fix Engineer

## Summary

Resolved AAR-002. Rewrote Argon2id `Verify` with strict format parsing, defensive
parameter limits, and comprehensive error handling. All format errors map to
`ErrInvalidCredentials` for clients while remaining distinguishable via exported
sentinel errors for testing.

## Hardened Verification

### Parser validation

| Check | Rejected value | Error sentinel |
|---|---|---|
| Segment count != 6 (split by `$`) | `$argon2id$v=19$` (truncated) | `ErrArgon2InvalidFormat` |
| Algorithm != `argon2id` | `$argon2i$...` | `ErrArgon2Algorithm` |
| Version != `v=19` | `$argon2id$v=20$...` | `ErrArgon2Version` |
| Unknown parameter key | `...$x=1$...` | `ErrArgon2InvalidFormat` |
| Duplicate parameter | `...$m=1,m=2$...` | `ErrArgon2DuplicateParam` |
| Non-numeric value | `...$m=abc$...` | `ErrArgon2InvalidValue` |
| Zero value (m, t, or p) | `...$m=0$...` | `ErrArgon2InvalidValue` |
| Empty salt | `...$$hash` | `ErrArgon2EmptySalt` |
| Empty hash | `...$salt$` | `ErrArgon2EmptyHash` |
| Invalid base64 salt | `...$!!!$hash` | `ErrArgon2Base64Salt` |
| Invalid base64 hash | `...$salt$!!!` | `ErrArgon2Base64Hash` |

### Defensive limits

| Parameter | Limit | Rationale |
|---|---|---|
| Memory (m) | ≤ 256 MiB | Prevents resource exhaustion |
| Iterations (t) | ≤ 10 | Current default is 3 |
| Parallelism (p) | ≤ 8 | Current default is 2 |
| Key length | ≤ 128 bytes | Current default is 32 |

### Error wrapping

All verification errors use `fmt.Errorf("%w: %w", identity.ErrInvalidCredentials, <internal>)`.
This means:
- Clients always see `ErrInvalidCredentials` → 401
- Internal tests can use `errors.Is(err, pgx.ErrArgon2MemoryTooHigh)` for diagnostics
- Two-pass unwrapping: `errors.Is(err, identity.ErrInvalidCredentials)` is always true

## Security Analysis

- Constant-time comparison preserved (`subtle.ConstantTimeCompare`)
- No timing leak: all format checks happen before password derivation, and invalid
  format returns same error type as wrong password
- Malicious hash cannot trigger DoS: memory/iterations/parallelism bounded
- Salt cannot be empty (would make hash deterministic)
- Base64 validation prevents injection via encoded payload
