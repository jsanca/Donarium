# DON-008.2 — Resolve Authenticated Principal

**Status:** COMPLETE
**Owner:** Deep
**Role:** Implementation Engineer

## Summary

Implemented the read side of Donarium's stateless authentication protocol.
Session cookie → verify signed token → extract subject → resolve current
permissions from PostgreSQL → attach principal to request context → `GET /api/auth/me`.

## Architecture

```
Request with donarium_session cookie
    │
    ▼
AuthenticationMiddleware (Chi middleware)
    ├── SessionCookieReader.Read → cookie value
    ├── SessionVerifier.Verify → SessionClaims (HMAC-SHA256 verify)
    │   ├── constant-time signature comparison
    │   ├── payload validation (sub, iat, exp)
    │   ├── clock-skew tolerance (1 min)
    │   └── expiration check
    ├── PrincipalResolver.Resolve → AuthenticatedPrincipal
    │   ├── FindByID (user)
    │   ├── loadPlatformGrant
    │   ├── loadOrganizationContexts
    │   └── determineDefaultContext
    └── context.WithValue → next handler

GET /api/auth/me
    ├── PrincipalFromContext(ctx)
    └── LoginResponse JSON (no session token)
```

## State

- **Stateless:** Yes. No HttpSession, no in-memory map, no Redis, no server-side session store.
- **Principal reconstruction:** Every request independently resolves from signed cookie + PostgreSQL.
- **Permissions:** Loaded from current persistence state (not from token payload).
- **Context attachment:** Typed `contextKey` via `context.WithValue`, request-scoped only.
- **Token payload:** Only `sub` (user UUID), `iat`, `exp`. No permissions embedded.

## HTTP Contract

| Scenario | Status | Body |
|---|---|---|
| Valid cookie | 200 | `{"principal":{...}}` |
| No cookie / empty / invalid sig / expired / user deleted | 401 | `{"error":"authentication required"}` |
| DB unavailable | 500 | `{"error":"internal server error"}` |
