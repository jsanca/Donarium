# DON-008.3 — Authorization Context and Route Guards

**Status:** COMPLETE
**Owner:** Deep
**Role:** Implementation Engineer

## Summary

Built the authorization layer on top of authentication. Separates "who are you?"
(authentication) from "what are you allowed to do?" (authorization). Introduces
composable middleware that consumes `AuthenticatedPrincipal` from request context
only — no cookie parsing, no token verification, no repository access.

## Architecture

```
Authentication layer (DON-008.2)
    │
    ├── Cookie → SessionVerifier → PrincipalResolver → context
    │
    ▼
Authorization layer (this slice)
    │
    ├── RequireAuthenticated()           ← 401 if missing
    ├── RequirePlatformRole(role)        ← 403 if missing
    ├── RequireOrganizationRole(role)    ← 403 if missing
    │
    ├── HasPlatformRole(principal, role) → bool
    └── HasOrganizationRole(principal, role) → bool
```

## Error Contract

| Condition | Status | Body |
|---|---|---|
| Authentication required (no principal) | 401 | `{"error":"authentication required"}` |
| Insufficient permissions | 403 | `{"error":"insufficient permissions"}` |
| Internal failure | 500 | `{"error":"internal server error"}` |

## Route Protection

`GET /api/auth/me` now protected by both `RequireAuthentication` + `RequireAuthenticated()`.
