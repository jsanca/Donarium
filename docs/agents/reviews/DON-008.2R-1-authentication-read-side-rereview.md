# DON-008.2R-1 — Targeted Architecture Re-Review: Authentication Read Side

- **Reviewer:** Elito
- **Date:** 2026-07-22
- **Scope:** DON-008.2-F2 resolution of AAR-001, AAR-002, and AAR-003 only
- **Verdict:** **CHANGES REQUIRED**

## Executive Summary

DON-008.2-F2 correctly removes role authorization from the authentication
package and adds router-level coverage for the public `/api/auth/me` flow.
The default-context rule is documented as earliest membership, but the SQL
ordering is only `created_at ASC`; equal timestamps have no secondary ordering.
Therefore the same persisted state does not yet have a guaranteed identical
principal/default context on every request. No regression was found in the
reviewed stateless verification, resolver reuse, context, or HTTP boundaries.

## Targeted Assessment

### AAR-001 — Authentication / Authorization Boundary

**Resolved.** `RequirePlatformRole`, `RequireOrganizationRole`,
`HasPlatformRole`, and `HasOrganizationRole` no longer exist in
`server/internal/identity/http`. They now belong to
`server/internal/identity/authorization/middleware.go`. Searches found no
authorization import or invocation from the authentication HTTP runtime or
authentication application package; `IdentityRuntime` still mounts only
`RequireAuthentication` and `RequireAuthenticated` for `/api/auth/me`.

The relocation is directionally coherent for the present scope: authorization
consumes the authenticated principal, while authentication does not depend on
authorization. No role guard is mounted on the read-side route.

### AAR-002 — Deterministic Default Context

**Not resolved.** The implementation documents earliest membership as the rule,
and `MembershipRepo.FindByUser` now includes `ORDER BY created_at ASC`.
That ordering is not total: two memberships with the same `created_at` may be
returned in either order by PostgreSQL because the query has no secondary key.
`determineDefaultContext` selects the first result, so a timestamp tie can
produce a different default organization from identical persisted state.

`TestResolve_DefaultContextDeterministicWithSameCreationDate` repeats a fake
repository that returns the same slice in the same order. It demonstrates
resolver stability for a preordered input, but it cannot verify the persistence
tie case. This is direct evidence that the required property has not yet been
proved or enforced.

### AAR-003 — Router Composition

**Resolved.** `server/internal/identity/http/me_router_test.go` builds the
public Chi route using the same `/api/auth/me` route group and middleware order
as `IdentityRuntime`. It verifies exact-path 401 paths (invalid, missing and
expired cookie), successful 200 principal JSON, content type, token absence,
405, and principal context propagation. The focused test design uses verifier
and resolver fakes, keeping the routing boundary isolated from database setup.

## Regression Review

- **Statelessness:** unchanged; no session map, cache, or stored principal was
  introduced.
- **Session verification:** not changed by DON-008.2-F2; HMAC verification still
  precedes trusting claims.
- **Principal reconstruction:** login and `/api/auth/me` still use the shared
  `PrincipalResolver`.
- **Request context:** typed context helper and request-scoped principal flow
  remain unchanged.
- **HTTP contract:** router tests confirm JSON `401`, JSON `200`, absence of
  session token, and `405` for the public path.
- **Error propagation:** no changes found to resolver/middleware mapping of
  operational failures to `500`.

## Findings

### AAR-002R-1 — Default-context ordering has no deterministic tie-breaker

- **Severity:** MAJOR
- **Category:** Determinism / persistence contract
- **Description:** The documented rule selects earliest membership, but
  `ORDER BY created_at ASC` leaves rows with equal timestamps unordered.
- **Evidence:** `server/internal/identity/pgx/membership_repository.go` orders
  only by `created_at`; `principal_resolver.go` selects element zero; the
  same-timestamp test uses a fake repository that returns the input sequence
  unchanged.
- **Impact:** A user with memberships sharing a timestamp can receive a
  different `defaultContext` between requests, violating the stateless
  reconstruction determinism required by AAR-002.
- **Recommendation:** Define a total ordering, such as `ORDER BY created_at ASC,
  organization_id ASC`, and add a persistence-aware or query-contract test for
  equal timestamps. If product semantics require another key, document it and
  use it consistently.
- **Disposition:** Required before DON-008.2 closeout.

## Positive Findings

- Authentication no longer exposes role-based guards or depends on the
  authorization package.
- The authorization relocation is not mounted in the authentication route tree.
- Router-level testing now protects the exact public `/api/auth/me` contract
  and middleware composition.
- No authentication read-side regression was found in statelessness, HMAC
  verification, principal reuse, context propagation, or error separation.

## Residual Risks

- AAR-004 remains an observation: session protocol versioning/key rotation and
  the equality expiration boundary need an intentional future policy.
- The architecture-closeout checkpoint for DON-008.2-F2 remains `OPEN`; this
  re-review does not alter that task record.

## Recommendation

**DON-008.2: FOLLOW-UP REQUIRED.** Add a stable secondary ordering criterion
and a test that covers equal creation timestamps, then perform a short
re-review of AAR-002. AAR-001 and AAR-003 are closed.
