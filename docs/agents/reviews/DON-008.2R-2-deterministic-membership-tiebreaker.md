## AAR-002 Verification

### Total ordering

`server/internal/identity/pgx/membership_repository.go` loads a user's
memberships with:

```sql
ORDER BY created_at ASC, organization_id ASC
```

`created_at` defines the primary order and `organization_id` defines the
secondary order. For equal creation timestamps, no ordering ambiguity remains.

### Documented default-context rule

`determineDefaultContext` in
`server/internal/identity/application/authentication/principal_resolver.go`
states that the earliest membership wins and that, when timestamps are equal,
the smallest organization identifier breaks the tie. It also explicitly
identifies the repository ordering as `created_at ASC, organization_id ASC`.
The documented behavior and the persistence query agree.

### Persistence contract test

`TestMembershipRepo_FindByUser_TieBreakerOrdering` in
`server/internal/identity/pgx/repository_test.go` uses the pgx repository and
test database rather than an in-memory ordering substitute. It persists two
memberships with equal `CreatedAt` values and different organization UUIDs,
calculates the lexically smaller identifier, and asserts it is returned first.
It repeats the query three times and asserts that the first membership remains
the same, covering the repeatability of the persistence contract.

### Required architectural property

```text
Same persisted state
  -> same ORDER BY created_at ASC, organization_id ASC result
  -> same first membership
  -> same default context
  -> same authenticated principal on every request
```

The stateless principal resolver consumes that ordered result on each request;
the tie-breaker therefore removes the remaining nondeterminism without
introducing stored authentication state.
