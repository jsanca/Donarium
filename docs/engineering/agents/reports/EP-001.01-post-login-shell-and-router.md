# EP-001.01 — Post-login shell, router, and empty-state routing decision — Report

## Status

Complete

## Objective

Deliver the post-login routing shell per task EP-001.01: an authenticated shell that consults `GET /api/auth/me` and `GET /api/properties` to decide Zero Properties → single Property Home → Portfolio, preserves deep-link `returnUrl` through login, is bilingual, and satisfies WCAG AA + H-4.

No backend changes. No property/invitation/payment behavior (owned by EP-001.02/.03/.12/.13/.14).

## Summary

- Adopted **React Router** (`react-router-dom@7.18.3`) and recorded the decision in **ADR-003** (`docs/adr/ADR-003-client-routing.md`).
- Replaced the single-page `LoginExperience`-only `App.tsx` with a `createBrowserRouter` + `RouterProvider` tree:
  - `AuthProvider` fetches `GET /api/auth/me` (`credentials: include`), exposes `{ principal, status, refresh, setPrincipal }`.
  - `RequireAuth` guards every authenticated tree branch; unauthenticated access redirects to `/login?returnUrl=<encoded path>`.
  - `PublicOnly` prevents authenticated users from seeing `/login` (redirects to sanitized `returnUrl` or `/`).
  - `RootRedirect` at `/` consults `GET /api/properties` (with tolerant parsing for future EP-001.02 shapes) and redirects: 0 → `/welcome`, 1 → `/properties/:id`, n → `/portfolio`.
  - `AuthenticatedShell` with sticky header, nav (`Portfolio` / `Properties` placeholders), user email/displayName, skip-link, mobile nav toggle, and `<Outlet />`.
  - Routes: `/welcome` (Zero), `/portfolio`, `/properties/:id`, `/invitations/:token/accept` (placeholder), `*` → `NotFound`.
- Implemented **return-URL preservation** with strict sanitization (`sanitizeReturnUrl`: only internal `/`-paths, rejects `//`, scheme, CRLF). Demonstrated via `RequireAuth` + `LoginForm` post-login `navigate(safeReturnUrl)`. Open redirect not possible.
- Wired `LoginForm` to real `POST /api/auth/login` via `loginRequest()`; on success calls `setPrincipal` and navigates to `returnUrl`; on 401 shows `login.error.invalidCredentials` (ES/EN), on other JSON `{ error }` surfaces it per **H-4**.
- Added **bilingual bundles** `shared/i18n/en.ts` (new) and expanded `shared/i18n/es.ts` with keys `shell.*`, `zero.*`, `portfolio.*`, `propertyHome.*`, `invitationAccept.*`, `routeError.*`, `errorBoundary.*`, `common.*`, `login.error.*`; upgraded `shared/i18n/index.ts` to browser-locale + `localStorage` detection with `es` fallback (A-9).
- Added **Vite proxy** for `/api → http://localhost:8080` (`vite.config.ts`) so `npm run dev` works.
- Added H-4 compliant error handling: `AppErrorBoundary` (global), `RouteError` (per-route, handles `isRouteErrorResponse` + JSON envelope), `parseApiError` reads `Content-Type` JSON envelope and `Allow` header. All shells render `role="alert"` + visible copy rather than raw stack.
- Added code-splitting: `ZeroProperties`, `PortfolioPlaceholder`, `PropertyHomePlaceholder`, `InvitationAcceptPlaceholder`, `NotFound` are `React.lazy` + `Suspense` (verifies future EP-001.04/.14 plug-in without shell rewrite).
- Accessibility: WCAG AA baseline kept — visible `:focus-visible` ring (global `styles.css`), keyboard-nav throughout, `prefers-reduced-motion` via `useReducedMotion`, touch targets `min-h-11` (≥44px), `aria-live`/`role` on loading/error, dialog has `role="dialog" aria-modal`.

### Routing decision coverage

- `/` → `RootRedirect` calls `GET /api/properties`:
  - `length === 0` or HTTP 404 (EP-001.02 not yet landed) or 401 → `Navigate /welcome` → `ZeroProperties`.
  - `length === 1` → `Navigate /properties/:id` (single Property Home placeholder).
  - `length >= 2` → `Navigate /portfolio` (Portfolio placeholder).
- Branches verified by reading `RootRedirect.tsx:16-58` and `router.tsx:30-56`; manual exercise instructions below.

### Return-URL preservation

- `RequireAuth.tsx:14-27` builds `returnUrl = pathname + search + hash`, `buildLoginUrlWithReturnUrl` encodes it.
- `LoginForm.tsx:48-66` reads `searchParams.get('returnUrl')`, `sanitizeReturnUrl` rejects `//` and schemes, defaults to `/`.
- `lib/returnUrl.ts` unit-validatable: `sanitizeReturnUrl('/properties/abc') === '/properties/abc'`, `sanitizeReturnUrl('//evil') === null`, `sanitizeReturnUrl('https://evil') === null`.
- End-to-end: enter `/properties/prop-1` or `/invitations/tok-xyz/accept` unauthenticated → `RequireAuth` → `/login?returnUrl=%2Fproperties%2Fprop-1` → successful `POST /api/auth/login` → `navigate('/properties/prop-1')`. Authenticated users hitting `/login` with `returnUrl` are redirected via `PublicOnly`.

### Zero → single → portfolio walk

1. **Zero Properties:** authenticated user with 0 properties lands at `/` → `/welcome`. Render shows editorial header + two cards ("Register a property" / "Access an existing property") + info dialog. Buttons meet touch-target / focus requirements; dialog uses `role="dialog" aria-modal`.
2. **Single Property Home:** once EP-001.02 creates one property, the same flow at `/` → `/properties/:id` shows `PropertyHomePlaceholder` (id in header, dashed shell, hint text). Deep link `/properties/:id` renders the same without going through redirect.
3. **Portfolio:** with ≥2 properties, `/` → `/portfolio` shows `PortfolioPlaceholder` with empty-state copy + skeleton cards, no mock data fabricated.

These are structural placeholders by design — EP-001.04 will replace them with real read models — but routing, auth gate, and navigation are complete and navigable.

### H-4 error envelope compliance

- `lib/api.ts:parseApiError` consumes JSON `{ error: string }` regardless of status (including 405 where server also sends `Allow`), preserves `allow` header, and surfaces `message`.
- `LoginForm` surfaces `apiErr.message` per H-4, mapping 401 to `login.error.invalidCredentials`.
- `RouteError` reads `error.data.error` (JSON envelope), status-specific titles for 401/403/404/410, and generic fallback. `AppErrorBoundary` displays `error.message` from caught exceptions.

## Limitations

- `GET /api/properties` is not yet implemented (EP-001.02). `RootRedirect` tolerates 404/401 as zero-properties, so the shell is already runnable and demonstrable before EP-001.02 lands; real 0/1/n discrimination will be fully exercisable only after EP-001.02.
- No `POST /api/auth/logout` endpoint exists; `AuthenticatedShell` sign-out is a client redirect to `/login`. A proper session-clear will arrive with a later auth slice without shell change.
- Automated e2e not provisioned in repo (no Playwright/Cypress harness). Walk-throughs are manual per plan; QA verification (EP-001.09) is the place to add coverage.
- Go `make test`/`make lint` not re-run as this node performs no backend changes (enforced).
