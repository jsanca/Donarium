## Summary

Addressed six of seven findings inside implementation authority; one graph finding is acknowledged but not owned by this Role.

- **AAR-001 (MAJOR, sign-out no-op):** Disabled the misleading control. `AuthenticatedShell` no longer calls `navigate('/login')`; it now renders a disabled `aria-disabled` span with `LogOut` icon at 60% opacity, cursor-not-allowed, and comment referencing the missing `POST /api/auth/logout` (httpOnly cookie cannot be cleared client-side). `PublicOnly` bounce no longer triggers.
- **AAR-002 (MAJOR, 401→zero conflation):** `RootRedirect` now treats 401 as authentication failure, not zero properties. On 401 it calls `setPrincipal(null)` (AuthProvider → `unauthenticated`) and returns `<Navigate to={buildLoginUrlWithReturnUrl(returnUrl)} replace />` with the snapshot `pathname+search+hash`. Reviewer-verified seam `404→zero` is kept as explicitly time-boxed with `TODO(EP-001.02)` to remove when `GET /api/properties` lands.
- **AAR-004 (MINOR, ADR-003 drift):** Amended `docs/adr/ADR-003-client-routing.md` to record the actual `AuthProvider` surface `{ status, principal, error, refresh, setPrincipal }` (enum, not boolean `loading`), note that `logout` is absent until a logout endpoint exists, and note the 401 propagation and disabled sign-out.
- **AAR-005 (MINOR, hardcoded English):** Routed all error/loading states through i18n:
  - `shared/ui/ErrorBoundary.tsx` now uses `i18n.t('errorBoundary.*')` for title/body/reload/goHome (class component)
  - `app/auth/RequireAuth.tsx` (`RequireAuth` + `PublicOnly`) now uses `useTranslation` → `t('common.loading')`, `t('errorBoundary.title')`, `t('routeError.unauthorizedBody')`, `t('login.submit')`
  - `app/routes/RootRedirect.tsx` now uses `t('common.loading')`, `t('routeError.title')`, `t('routeError.retry')`
  - `app/router.tsx` `LazyFallback` now uses `useTranslation` → `t('common.loading')` instead of literal `Loading…`
  - Keys `errorBoundary.*` and `common.*` already existed in both bundles and are now consumed.
- **AAR-006 (MINOR, divergent sanitization):** `PublicOnly` now imports and uses shared `sanitizeReturnUrl(raw) ?? '/'` (includes scheme/`//`/CRLF checks) instead of inline `startsWith` duplicate.
- **AAR-007 (OBSERVATION, misleading comment):** Corrected `app/lib/api.ts` trailing comment — it now states the throw-on-!ok behavior and that the 404→zero seam lives in `RootRedirect`, with `TODO(EP-001.02)`. `RootRedirect` already contains the matching time-boxed comment.
- **AAR-003 (MAJOR, graph/boundary — EP-001.06 i18n):** Acknowledged but not remediated by this Role. The i18n bundles and A-9 detection created by EP-001.01 indeed realize EP-001.06 scope; graph reconciliation (mark EP-001.06 absorbed/narrowed, update downstream edges for .04/.05/.14, or fold verification into EP-001.09/.11) requires `product-architect` / `knowledge-curator` per the review's own disposition. No code change in this node would correctly resolve a plan-graph inconsistency; an implementation-only fix would be boundary overreach. Recorded as open follow-up.

No backend change was introduced. No property/invitation/payment behavior was added.
