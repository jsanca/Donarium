# EP-001.02 — Property domain + `POST/GET /api/properties` — Report

## Status

Complete

## Objective

Deliver a first-class `Property` aggregate per EP-001.02: domain type, repository, application service, and HTTP surface. Expose `POST /api/properties` (identity + classification + address + rental cadence + standard rent), `GET /api/properties` (list accessible to authenticated User), and `GET /api/properties/{id}` (overview) with H-3/H-4 compliance, additive migration, and no Organization-scope column. Stakeholders, initial tenancy, payment log, and invitations remain out of scope and are owned by EP-001.03/.05/.12/.13.

## Summary

- Defined domain `server/internal/properties/`:
  - `property.go` — `PropertyID`, `Classification` enum (house, apartment, condominium, multi_unit, commercial, other) with case-insensitive `ParseClassification` accepting hyphen/underscore/space variants, `RentalCadence` enum (monthly, weekly, daily, annual), `Address` (street, city, state, postalCode, country) with validation, `Property` aggregate (CreatedBy UUID, CreatedAt/UpdatedAt, DisplayName 2–100 chars, StandardRent >0, <10M), and validation helpers.
  - `errors.go` — `ErrPropertyNotFound`, `ErrInvalidClassification`, etc.
  - `executor.go` — `DBExecutor`/`Rows`/`RowScanner` anti-corruption layer (boundary-preserving, mirrors `identity.DBExecutor` shape without cross-domain import).
  - `repository.go` — `Repository` interface (`Create`, `FindByID`, `FindAccessibleByUser`).
- Implemented persistence `properties/pgx/`:
  - `executor.go` — pgx pool/tx adapter for `properties.DBExecutor`.
  - `repository.go` — SQL for `properties` table, `Create`, `FindByID`, `FindAccessibleByUser`. Access seam is intentionally narrow: `WHERE created_by = $1 ORDER BY created_at ASC, id ASC`. Comment documents that EP-001.03 will extend this to join `property_stakeholders` + `memberships`; keeping the query isolated makes that a single-point change.
  - `transaction.go` — `TransactionManager` wrapping `pgxpool.Pool` (mirrors `identity/pgx/transaction.go`) satisfying `application.TransactionManager`.
- Implemented application `properties/application/service.go`:
  - `RegisterPropertyCommand`/`Result`, `Service` (repo + tx). `RegisterProperty` validates displayName/classification/address/cadence/rent, trims strings, parses enums, generates UUID/timestamps, and persists transactionally via `WithinTransaction`. `ListAccessible` delegates to repo. `GetByID` parses UUID, fetches, then enforces authorization by returning `ErrPropertyNotFound` for both not-found and unauthorized (no disclosure), matching OP-6/H-4. Invalid UUID also maps to `ErrPropertyNotFound`.
  - Reuses existing string-trim and validation conventions; no Organization-scope field anywhere.
- Added additive migration `server/internal/platform/database/migrations/006_properties.{up,down}.sql`:
  - Table `properties` with `id UUID PK`, `display_name` CHECK len 2–100, `classification` CHECK 6 values, address columns (`address_street`, `city`, `state`, `postal_code`, `country`), `rental_cadence` CHECK 4 values, `standard_rent BIGINT >0`, `created_by UUID FK users(id) RESTRICT`, timestamps, and index `idx_properties_created_by`. Down drops index and table. Additive and reversible per Appendix A.
- Implemented HTTP `properties/http/`:
  - `dto.go` — request/response DTOs (`AddressRequest`, `RegisterPropertyRequest`, `PropertyResponse` with ISO8601 timestamps, `ListPropertiesResponse{properties: []PropertyResponse}`).
  - `handler.go` — `Handler` with `Collection` dispatcher (GET → `ListProperties`, POST → `RegisterProperty`, else 405 with `Allow: GET, POST`), `RegisterProperty` (401 if no principal, 400 JSON for invalid body/displayName/classification/address/cadence/rent, 201 with `application/json`), `ListProperties` (401, 200 with `{properties: []}`), `GetProperty` (401, 400 for missing id, 404 with `property not found` for both not-found and unauthorized, 405 with `Allow: GET`), all via `writeError` JSON envelope and `Content-Type: application/json`. `mapDomainError` centralizes 400 mappings.
  - `runtime.go` — `Runtime` with `RegisterRoutes` mounting under `/api/properties` via `chi.Route` with `RequireAuthentication` + `RequireAuthenticated` middleware. Collection handles `"/"` and `""` to tolerate trailing-slash variance; `/{id}` handled via `HandleFunc` to ensure 405 includes `Allow` (H-4).
- Wired into `server/cmd/donarium/main.go`: instantiate `propertyRepo`, `propertyTx`, `propertyService`, `propertiesRuntime`, and include in `runtime.NewApplication` alongside `PlatformRuntime`/`IdentityRuntime`. Reuses existing `authMiddleware` (no new auth code).
- Removed the temporary `404→zero` seam in `client/src/app/routes/RootRedirect.tsx` (AAR-007 cleanup) and updated `client/src/app/lib/api.ts` comment to reflect that `GET /api/properties` now exists (`{properties: [...]}`) with tolerant parsing kept for forward compatibility. This closes the downstream handoff noted in EP-001.01F.
- All new integration test packages enforce **H-3** explicitly: `TEST_DATABASE_URL` pool creation/ ping failures `panic` with explanatory message rather than `os.Exit(0)` silent-pass.

## Limitations

- Integration suites requiring PostgreSQL were not green in this environment (no Docker/PostgreSQL available; `dial tcp [::1]:5432: connection refused`). Tests fail explicitly per H-3 rather than silently passing; full green requires `make postgres-up` or a `TEST_DATABASE_URL` host. This is the correct hygiene per the plan.
- Access rule is `CreatedBy`-only until EP-001.03 lands; `FindAccessibleByUser` seam is documented and isolated but not yet stakeholder-aware. This is the intended handoff and does not violate the access rule (which is defined to be finalized in EP-001.03).
- No end-to-end `httptest` through the full `runtime.NewApplication` with real `AuthenticationMiddleware` (which would require HMAC session cookies) — handler tests inject `Principal` via context. Full auth-through-middleware coverage is deferred to EP-001.07 (deep-link auth) and QA EP-001.09.
- `DELETE`, `PATCH` on `/api/properties` correctly returns `Allow: GET, POST` (collection) but `GET /api/properties/{id}` with `POST` returns `Allow: GET` via handler; chi's global `MethodNotAllowed` for unknown routes still lacks `Allow` — not exercised by new endpoints but noted.
