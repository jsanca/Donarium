# EP-001.03 — Party model + PropertyStakeholder + Wizard Step 2 — Report

## Status

Complete

## Objective

Introduce `Party` (`UserRef` | `OrganizationRef` | `ExternalParty`) and `PropertyStakeholder(PropertyID, Party, Role, CreatedAt)` with uniqueness `(PropertyID, Party, Role)` per A-12, extend `RegisterProperty` to persist declared stakeholders atomically, finalize the Property access rule (UserRef direct OR OrganizationRef via Membership; ExternalParty never confers access), and expose Wizard Step 2's four Stitch relationship options. `Membership`/`OrganizationRole` remain untouched (H-2).

## Summary

- **Domain** `server/internal/properties/party.go` + `stakeholder.go`:
  - `PartyType` (`user`, `organization`, `external`), `Party{Type, UserID *UUID, OrganizationID *UUID, ExternalName, ExternalEmail}` with `Validate()` (exactly one variant, external name 2–100, email via `mail.ParseAddress`, normalized lower), `ReferenceKey()` for uniqueness.
  - `StakeholderRole` (`owner`, `manager`), `ParseStakeholderRole` case-insensitive, `PropertyStakeholder{PropertyID, Party, Role, CreatedAt}` with `NewPropertyStakeholder` validation.
  - `errors.go` extended with `ErrInvalidParty`, `ErrInvalidStakeholderRole`, `ErrInvalidStakeholder`, `ErrDuplicateStakeholder`, `ErrNoStakeholder`.
  - `property_test.go` unit tests for `ParseClassification`/`ParseRentalCadence` remain; stakeholders add no new unit-only tests but are covered via integration.

- **Migration** `007_property_stakeholders.{up,down}.sql` (additive, reversible):
  - Table `property_stakeholders` with `property_id FK properties CASCADE`, `party_type CHECK ('user','organization','external')`, `party_user_id FK users CASCADE`, `party_org_id FK organizations CASCADE`, `party_external_name/email` nullable, `role CHECK ('owner','manager')`, `created_at`, `chk_party_user/org/external` ensuring column coherence per type, `chk_external_email` regex, unique index `uq_property_stakeholder` on `(property_id, party_type, COALESCE(party_user_id::text,''), COALESCE(party_org_id::text,''), COALESCE(lower(party_external_email),''), role)` per A-12 (same Party may hold both roles), plus indexes on `property_id`, `party_user_id` (user), `party_org_id` (org). Down drops indexes and table.

- **Repository seam finalization**:
  - `repository.go` extended with `StakeholderRepository` interface (`Create`, `FindByProperty`, `FindAccessiblePropertyIDs`, `HasAccess`).
  - `pgx/repository.go:70` `FindAccessibleByUser` rewritten from `WHERE created_by = $1` to stakeholder join: `SELECT DISTINCT p.* FROM properties p JOIN property_stakeholders ps ON ps.property_id=p.id LEFT JOIN memberships m ON ... WHERE (ps.party_type='user' AND ps.party_user_id=$1) OR (ps.party_type='organization' AND m.user_id IS NOT NULL) ORDER BY created_at, id`. This is the sole access path after EP-001.03.
  - `pgx/stakeholder_repository.go` new: `Create` (validates party, inserts, maps duplicate key to `ErrDuplicateStakeholder`), `FindByProperty` (ordered by `created_at, role`), `HasAccess` (`SELECT 1 ... LIMIT 1` with same join), `FindAccessiblePropertyIDs`. Uses `properties.DBExecutor`; no identity import.

- **Application** `application/service.go`:
  - `RegisterPropertyCommand` now includes `Stakeholders []StakeholderInput` (`PartyInput{Type, UserID, OrganizationID, ExternalName, ExternalEmail}`, `Role string`).
  - `Service` now holds `repo`, `stakeholderRepo`, `tx`; constructors `NewService(repo, tx)` (legacy, nil stakeholderRepo for backward compat) and `NewServiceWithStakeholders(repo, stakeholderRepo, tx)` (wired in `cmd/donarium/main.go`).
  - `RegisterProperty` validates displayName/classification/address/cadence/rent, parses stakeholders via `parseStakeholders` (party type inferred if omitted, UUID parsing, role parsing, `Party.Validate()`), deduplicates by `(partyType, reference, role)` to enforce A-12 before DB, defaults to two stakeholders `UserRef(actor)` OWNER + MANAGER when `len==0` (covers Stitch option 1 "I am both" and keeps EP-001.02 callers working), validates `ExternalParty` name/email, then inside `WithinTransaction` checks existence of referenced `User`/`Organization` (`SELECT 1 FROM users/organizations`), verifies at least one stakeholder ties the actor: direct `UserRef(actor)` or `OrganizationRef` where actor has `memberships` row (external never ties). If `stakeholderRepo==nil` (legacy), only direct tie is checked. Then creates `Property` and each `PropertyStakeholder` atomically; duplicate maps to `ErrDuplicateStakeholder`.
  - `ListAccessible` delegates to `repo.FindAccessibleByUser` (now stakeholder-based).
  - `GetByID` fetches property, then checks `stakeholderRepo.HasAccess` (or legacy `CreatedBy` fallback when nil) and returns `ErrPropertyNotFound` for both not-found and unauthorized (no disclosure, H-4/OP-6).

- **HTTP** `http/dto.go` + `handler.go`:
  - `dto.go` adds `PartyRequest{Type, UserID, OrganizationID, ExternalName, ExternalEmail}`, `StakeholderRequest{Party, Role}`, and `RegisterPropertyRequest.Stakeholders []StakeholderRequest`.
  - `handler.go` maps `StakeholderRequest` to `StakeholderInput`, extends `mapDomainError` to 400 for `ErrInvalidParty`/`ErrInvalidStakeholderRole`/`ErrInvalidStakeholder`, 409 for `ErrDuplicateStakeholder`, 400 for `ErrNoStakeholder`. `RegisterProperty` still returns 201 with `PropertyResponse` (stakeholders not echoed; fetch via stakeholder repo). Existing `Collection` 405 `Allow: GET, POST` and `GetProperty` 405 `Allow: GET` and JSON envelope preserved.

- **ADRs** placed under `docs/adr/`:
  - `ADR-004-property-stakeholder-relation.md` — per-property relation vs extending `OrganizationRole`/`Membership`; preserves identity boundary, additive migration, transactional persistence, access via join.
  - `ADR-005-party-model.md` — `UserRef` | `OrganizationRef` | `ExternalParty` discriminated Party; external never confers access; Wizard four options mapped to stakeholder rows.

- **Wiring** `cmd/donarium/main.go:94` now instantiates `stakeholderRepo := propertiespgx.NewStakeholderRepository()` and `propertyService := propertiesApp.NewServiceWithStakeholders(propertyRepo, stakeholderRepo, propertyTx)` before `propertieshttp.NewRuntime`.

- **Client**: No UI change in this node; Wizard Step 2's four Stitch options are backend-contract-complete. The API contract `{stakeholders: [{party: {type, userId/organizationId/externalName/externalEmail}, role}]}` supports all four: (1) self both, (2) self manager + external owner, (3) self owner + external manager, (4) organization owner + self manager. EP-001.04 will consume the resulting attribution for Property Home header.

### Four Stitch options (integration)

- `application/service_test.go:TestService_FourStitchOptions:1` creates a user `uid`, then:
  - Opt1 `user:uid owner + user:uid manager` → `RegisterProperty` succeeds, `FindByProperty` returns 2 rows (`user:owner`, `user:manager`).
  - Opt2 `user:uid manager + external owner` → succeeds, 2 rows.
  - Opt3 `user:uid owner + external manager` → succeeds, 2 rows.
  - Opt4 creates `organization` `test-org-opt4` owned by `uid`, membership `owner` for `uid`, then `organization:org owner + user:uid manager` → succeeds, 2 rows.
  - Final `ListAccessible(uid)` returns 4 properties, verifying all four are accessible via the actor tie.

### Access rule

- `application/service_test.go:TestService_AccessRule_UserDirectAndViaOrganizationAndExternalNoAccess:1`:
  - `uidOwner` direct `user:uidOwner owner` → `ListAccessible(uidOwner)` contains it, `GetByID` succeeds for owner.

## Limitations

- No Property editing after registration; stakeholders are immutable post-create. Editing is out of this node.
- No invitation or payment behavior; `ExternalParty` is contact-only and cannot be resolved to a `User` in this slice (EP-001.13 will create `UserRef` on acceptance).
- Client Wizard Step 2 UI not implemented; the API contract above is the Wizard's backend seam. EP-001.04 will surface the resulting attribution in Property Home header.
- No end-to-end `httptest` through full `runtime.NewApplication` with real `AuthenticationMiddleware` (session cookie); handler tests inject `Principal` via `identityhttp.WithPrincipal`.
