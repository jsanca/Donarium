# EP-001.K01 — Knowledge Layout and Architecture Views Reconciliation — Report

- **Assigned Role:** `knowledge-curator` (OSK role v0.1.0)
- **Status:** Complete
- **Mode:** Reconciliation (authorized corrections only; no application/behavior change)

## Objective

Reconcile Donarium's knowledge layout to the single canonical OSK topology, and
author the navigable architecture/package views and current database ER diagram
that the layout references — without changing application behavior or deciding
product intent.

## Summary

The repository carried durable knowledge in two competing locations:
`knowledge/` at the repo root (ADRs, design, use cases, business rules, test
cases, testing) and `docs/` (which already held `docs/knowledge/`, `docs/adr/`,
`docs/roadmap/`, `docs/engineering/` as empty/README scaffolds). The OSK
workspace guide (`docs/OSK.md`) and each area README defined the canonical
locations under `docs/`, but the substance still lived at the root. This task
moved the substance into the canonical `docs/` tree and authored the missing
architecture views and ER diagram.
