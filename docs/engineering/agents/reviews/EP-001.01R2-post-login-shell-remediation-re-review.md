## Disposition of findings

### AAR-001 — misleading/non-functional Sign out — RESOLVED

- `AuthenticatedShell.tsx` no longer imports `useNavigate` and has no
  `handleSignOut`. The control is now a disabled `<span aria-disabled="true">`
  (LogOut icon at `opacity-60`, `cursor-not-allowed`) with an explanatory
  comment. No `navigate('/login')`, no `setPrincipal(null)` fake logout, no
  client-side cookie manipulation, and no backend logout capability added.
- Verification criteria met: no UI action claims to terminate the session; no
  fake client-side logout; no backend logout introduced. The
  `PublicOnly` bounce is therefore no longer reachable via this control.

### AAR-002 — HTTP 401 interpreted as zero properties — RESOLVED

- `RootRedirect.tsx` now models an explicit `unauthenticated` state. On 401 it
  calls `setPrincipal(null)` and `setState({ status: 'unauthenticated',
  returnUrl })`, rendering `<Navigate to={buildLoginUrlWithReturnUrl(...)}
  replace />`. 401 no longer routes to `/welcome`.
- return-URL preservation remains safe: the snapshot is
  `location.pathname + location.search + location.hash`, passed through
  `buildLoginUrlWithReturnUrl`, and re-validated on the login side by
  `sanitizeReturnUrl`.
- The temporary 404 → zero seam is retained and bounded with
  `TODO(EP-001.02)` (both in `RootRedirect` and `lib/api.ts`), limited to the
  unimplemented-endpoint compatibility window.

### AAR-004 — ADR-003 AuthProvider contract drift — RESOLVED

- ADR-003 §Decisión now records the actual surface `{ status, principal, error,
  refresh, setPrincipal }` with `status` as an enum (not a boolean `loading`),
  notes that `logout` is not exposed until `POST /api/auth/logout` exists, and
  documents the disabled sign-out and the 401 propagation in `RootRedirect`
  (§Consecuencias). The decision now matches the implementation.

### AAR-005 — hardcoded-English error/loading states — RESOLVED

- `ErrorBoundary.tsx` renders via `i18n.t('errorBoundary.*')`.
- `RequireAuth`/`PublicOnly` use `t('common.loading')`, `t('errorBoundary.title')`,
  `t('routeError.unauthorizedBody')`, `t('login.submit')`.
- `RootRedirect` uses `t('common.loading')`, `t('routeError.title')`,
  `t('routeError.retry')`.
- `router.tsx` `LazyFallback` uses `t('common.loading')`.
- Grep confirms no equivalent hardcoded-English replacement was introduced. The
  `errorBoundary.*` and `common.*` keys are now consumed by both bundles.

### AAR-006 — divergent PublicOnly return-URL sanitizer — RESOLVED

- `RequireAuth.tsx` `PublicOnly` now uses the shared `sanitizeReturnUrl(raw) ??
  '/'` (scheme, `//`, and CRLF rejection). The inline duplicate is removed.
  Open-redirect protection has not regressed (LoginForm, RequireAuth, and
  RootRedirect all route through the same sanitizer path).

### AAR-007 — misleading fetchProperties documentation — RESOLVED (doc-only)

- `lib/api.ts` comment now states the throw-on-non-2xx behavior and that the
  404 → zero seam lives in `RootRedirect`'s catch, with `TODO(EP-001.02)`.
  The seam itself was not prematurely changed, as required.

### AAR-003 — graph/boundary (EP-001.06 i18n) — REMAINS OPEN (not in scope)

- Confirmed still open and correctly out of this remediation. No graph
  reconciliation was performed and none is claimed by EP-001.01F. Remains owned
  by `product-architect` / `knowledge-curator`.

## Regression check

No regressions directly caused by EP-001.01F were found:

- Auth flow, routing tree, lazy loading, and return-URL preservation are intact.
- The `setPrincipal(null)` + local `unauthenticated` state on 401 resolves
  without a render loop: the parent `RequireAuth` observes `unauthenticated`
  and redirects, unmounting `RootRedirect` before any effect re-run.
- The disabled sign-out is a passive, non-focusable indicator; it introduces no
  broken navigation.

Two pre-existing, out-of-scope items are noted for awareness only (not
introduced by, and not reopened under, this remediation): `AuthenticatedShell`
still hardcodes the mobile-menu `aria-label` ("Open menu"/"Close menu") and the
"Donarium" brand wordmark; ADR-003 still refers to `RouteErrorBoundary` while the
component is `RouteError`. Neither was part of AAR-005's scope.

## Verdict

**PASS.** All six findings assigned to `software-engineer`
(AAR-001, AAR-002, AAR-004, AAR-005, AAR-006, AAR-007) are resolved and
independently verified against the implementation. The remediation branch passes
engineering review.

**EP-001.01 closure:** EP-001.01 may be accepted from the engineering-review
perspective. AAR-003 remains OPEN and must be reconciled by `product-architect`
(`knowledge-curator` for log materialization) before the EP-001 graph is
consistent — but it does not block the software-engineering remediation, and it
does not prevent downstream EP-001.04/.14 from consuming the shell handoff.
AAR-007's `TODO(EP-001.02)` (removal of the 404 → zero seam) must be honored when
`GET /api/properties` lands.
