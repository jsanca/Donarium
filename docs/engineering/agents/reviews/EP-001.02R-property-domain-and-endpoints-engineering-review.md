## Findings

### 02R-001 — Monetary unit for `standardRent` is undocumented

- **Severity:** MINOR
- **Type:** documentation/contract concern
- **Affected:** `server/internal/properties/property.go:104-135`; `http/dto.go:21-31`.
- **Evidence:** `StandardRent int64` carries no unit in the type, field name, or
  DTO. The convention (integer minor units / cents) is only inferable from the
  report and the `// 10M in cents` comment; the JSON field is the bare
  `standardRent`.
- **Impact:** Downstream consumers (EP-001.04 Portfolio/Property Home cards,
  EP-001.12 payment log) must render and compare amounts consistently. A bare
  integer without an explicit unit invites a display/parity bug (e.g., treating
  `120000` as $120,000.00 vs $1,200.00) and complicates the future Payments
  boundary.
- **Recommendation:** Document the minor-unit convention explicitly in the
  domain type (or introduce a small `Money` type with a unit comment) and
  consider a `currency` dimension only if/when the product requires it.
- **Disposition:** Follow-up; owner `software-engineer` (EP-001.02 doc fix or
  `knowledge-curator` at EP-001.11).

### 02R-002 — No end-to-end router/middleware integration test

- **Severity:** MINOR
- **Type:** verification concern
- **Affected:** `properties/http/handler_test.go` (injects principal directly).
- **Evidence:** Handler tests call `Handler` methods with a principal injected
  via `WithPrincipal`, and never mount `runtime.NewApplication` /
  `PropertiesRuntime.RegisterRoutes` through `RequireAuthentication` with a real
  session cookie. The 401 path is asserted only at handler level, not through
  the cookie-verifying middleware chain.
- **Impact:** Route composition, middleware ordering, trailing-slash tolerance,
  and the true 401/405/`Allow` behavior at the HTTP boundary are inferred, not
  regression-protected.
- **Recommendation:** Add one focused router-level test (using a fake verifier/
  resolver) in EP-001.07 (deep-link auth) or EP-001.09 (QA), asserting the public
  paths and 401/200/400/404/405 + `Allow`.
- **Disposition:** Follow-up; owner `software-engineer` (EP-001.07) / `qa-engineer`
  (EP-001.09).

### 02R-003 — `ValidateStandardRent` cap comment is off by ~100×

- **Severity:** OBSERVATION
- **Affected:** `server/internal/properties/property.go:131`.
- **Evidence:** The constant is `1_000_000_000_00` (100,000,000,000 cents ≈
  $1,000,000,000), but the comment reads `// 10M in cents`. The report's summary
  also states `<10M`.
- **Impact:** Functionally harmless — the cap remains a generous sanity bound —
  but the comment misstates the magnitude by ~100× and could mislead future
  maintenance.
- **Recommendation:** Correct the comment (or the constant) to match intent.
- **Disposition:** Follow-up; owner `software-engineer`.

### 02R-004 — `DBExecutor`/`TransactionManager` ports duplicated across domains

- **Severity:** OBSERVATION
- **Affected:** `properties/executor.go`, `properties/pgx/transaction.go` mirror
  `identity/executor.go`, `identity/pgx/transaction.go`.
- **Evidence:** The `properties.DBExecutor`/`Rows`/`RowScanner` interfaces and the
  pgx `TransactionManager` are byte-for-byte the same shape as the identity
  equivalents, intentionally duplicated as an anti-corruption layer so the
  domains do not import each other.
- **Impact:** None today; this is correct bounded-context isolation. It is noted
  only because a third domain would make a shared `platform/database` port the
  higher-leverage choice.
- **Recommendation:** Defer. Consolidate into a shared port only when a third
  consumer appears.
- **Disposition:** No action now.

### 02R-005 — Platform-level `MethodNotAllowed` handler omits `Allow`

- **Severity:** OBSERVATION
- **Affected:** `server/internal/platform/runtime/application.go:92-96`.
- **Evidence:** The global `methodNotAllowedHandler` returns JSON `{error}`
  but never sets an `Allow` header. EP-001.02 endpoints are unaffected because
  they register via `HandleFunc` and set `Allow` in their own method checks
  (verified by `TestHandler_405_Collection`, `TestHandler_405_GetProperty`).
- **Impact:** Pre-existing platform behavior, not introduced here. It will bite
  the first method-specific route registration.
- **Recommendation:** Track as a platform hygiene follow-up so all future 405s
  satisfy H-4 uniformly.
- **Disposition:** Owner `platform-engineer` (opportunistic).

## Review-question assessment

1. **Scope / no absorption** — PASS. No stakeholder, tenancy, payment, or
   invitation behavior was implemented; `created_by` is a bounded seam, not a
   new domain concept.
2. **Domain model vs PA decisions** — PASS. No Organization-scope column;
   Property is canonical; classification/cadence use the approved OP-5/A-10
   values; `created_by` is provenance, not ownership.
3. **Repository/persistence boundaries** — PASS. Ports are consumer capabilities
   (anti-corruption isolation), not gratuitous indirection (see 02R-004).
4. **`created_by` as bounded seam** — PASS. Documented, isolated, narrower than
   the final rule; replaced by EP-001.03.
5. **Domain values/validation** — PASS. Within engineering authority; enums
   normalize aliases to canonical values before storage.
6. **Monetary/rent semantics** — PASS with note. Integer minor units are
   adequate for the scope; the unit is under-documented (02R-001).
7. **HTTP contracts** — PASS. 401/400/404/201/405 with `Allow` and JSON envelope
   verified; non-disclosure semantics correct.
8. **Migration `006_properties`** — PASS. Additive, reversible, FK/CHECK/index
   appropriate; ready for EP-001.10.
9. **Tests** — PASS. Unit tests always run; DB-dependent suites fail explicitly
   (H-3) — verified by execution.
10. **Client 404 → zero seam removal** — PASS. `RootRedirect` no longer maps 404
    to zero; `api.ts` reflects the `{properties:[…]}` shape.

## Positive Findings

- Clean domain isolation: `properties` does not import `identity`; the
  anti-corruption `DBExecutor` keeps bounded contexts decoupled.
- Non-disclosure is correct and consistent (404 for not-found and unauthorized;
  invalid UUID also maps to 404), satisfying OP-6/H-4.
- H-4 `Allow` + JSON error envelope is consistently applied across 405/400/401.
- H-3 is genuinely enforced: DB tests panic and FAIL without PostgreSQL (verified
  by direct execution), not silently passing.
- Additive, reversible migration with appropriate CHECKs and index.
- Client seam removal closes the EP-001.01 AAR-007 handoff cleanly.
- `RegisterProperty` validates all fields before opening the transaction and
  trims strings; UUIDs/timestamps are generated in the application layer.

## Verdict

**PASS WITH FINDINGS.** No BLOCKER or MAJOR findings. The implementation
correctly realizes EP-001.02 and does not absorb adjacent-node work. EP-001.02
may be accepted from the engineering-review perspective.

Downstream nodes may safely consume it, with three conditions: (a) EP-001.03
replaces the `created_by` access seam; (b) EP-001.04/.12 agree on the
`standardRent` unit (02R-001); (c) EP-001.07/.09 close the router-level
integration-test gap (02R-002).
