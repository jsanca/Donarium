## Intent and outcome

Portfolio and Property Home pages render with real identity, stakeholders, specifications, and payment-log content; incidents / documents / milestones sections render explicit empty states. Portfolio supports minimum filters (All / Managed by You / Owned by You / Invited by You) and minimum sort (Recently Changed). Cards apply the "3-signal" principle per plan OP-8: render the most relevant available signals from {financial, attention, next milestone}; may render fewer; never fabricate.

## Relevant context and requirements

- Attribution (Managed by / Owned by) is derived from `PropertyStakeholder` (EP-001.03).
- Payment section content is fetched from EP-001.12 endpoints.
- Bilingual copy via EP-001.06.
- Design Constitution and Stitch theme guidance from the plan apply.

## Constraints / established direction

- No mock data. Sections without a supporting domain render explicit empty states.
- OP-8 principle enforced: never invent missing signals.
- Complies with plan hygiene **H-4** for client error surfaces.

## Expected evidence

- UI walkthrough of Zero → 1 property → multi-property transitions.
- Property Home rendering evidence for both fully-populated and mostly-empty properties.
- Portfolio filter and sort behavior evidence.
- Screenshots or notes preserved in the report.
- Report at `docs/engineering/agents/reports/EP-001.04-portfolio-and-property-home-read-model.md`.

## Handoff / stop condition

Portfolio and Property Home are readable. Editing existing properties or their stakeholders is out of this node.
