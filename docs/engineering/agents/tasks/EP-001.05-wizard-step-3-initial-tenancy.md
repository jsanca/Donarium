## Intent and outcome

Registration captures an initial tenancy declaration: `Occupied` (tenant contact + expiry date + payment-due day + security deposit) or `Vacant`. The declaration is stored on the Property record. **No `Lease` entity is introduced.**

## Relevant context and requirements

- Structured so that a future Leases slice can promote the initial tenancy into a real `Lease` without a destructive migration (plan A-6).
- Bilingual copy via EP-001.06.

## Constraints / established direction

- Additive Property columns or a small `PropertyInitialTenancy` record — implementation choice within Role authority.
- No Lease semantics: no term arithmetic, no renewal, no expiry alerts.

## Expected evidence

- Round-trip evidence for both Occupied and Vacant paths.
- Explicit no-op behavior when Vacant is declared.
- Migration draft included for EP-001.10 review.
- Report at `docs/engineering/agents/reports/EP-001.05-wizard-step-3-initial-tenancy.md`.

## Handoff / stop condition

Registration captures the initial tenancy declaration. Editing tenancy after registration and any Lease semantics are out of this node.
