# EP-001.06 — Bilingual i18n materialization (ES/EN, frontend only)

- **Plan:** [EP-001 — First Property Experience](../../plans/DONARIUM-PA-EXP-001-first-property-experience-engineering-plan-proposal.md) (APPROVED r3, 2026-09-02)
- **Assigned Role:** `software-engineer` (v0.2.0)
- **Status:** MATERIALIZED — awaiting Role adoption
- **Depends on:** none
- **Blocks:** EP-001.01, EP-001.04, EP-001.05, EP-001.14 (copy fan-in)
- **Permitted parallelism:** fully independent; schedule early to remove copy rework

## Intent and outcome

`client/src/shared/i18n/` gains an EN bundle alongside the existing ES bundle. All new keys for the EP-001 experience are present in both. Language selection defaults per plan A-9: browser locale + persisted preference in `localStorage`; ES fallback if neither ES nor EN.

## Relevant context and requirements

- Only frontend i18n. **No backend i18n.**
- No Settings-based language switcher in EP-001.
- Preserve the existing i18n approach (i18next + `es.ts`).

## Constraints / established direction

- Parity between ES and EN bundles for every new key emitted by the experience.
- Language default behavior implemented once; consumed by every UI node.

## Expected evidence

- Both bundles present with parity for the EP-001 keys.
- Language default demonstrated in a browser under each of {ES locale, EN locale, other locale} configurations.
- Persistence of the preference in `localStorage` demonstrated.
- Report at `docs/engineering/agents/reports/EP-001.06-bilingual-i18n-materialization.md`.

## Handoff / stop condition

Copy and language selection are available for consuming nodes. A Settings-based switcher and any per-user server-persisted preference are out of this node.
