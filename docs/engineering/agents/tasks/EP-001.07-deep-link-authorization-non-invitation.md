# EP-001.07 — Deep-link `/properties/:id` authorization (non-invitation)

- **Plan:** [EP-001 — First Property Experience](../../plans/DONARIUM-PA-EXP-001-first-property-experience-engineering-plan-proposal.md) (APPROVED r3, 2026-09-02)
- **Assigned Role:** `software-engineer` (v0.2.0)
- **Status:** MATERIALIZED — awaiting Role adoption
- **Depends on:** EP-001.02
- **Blocks:** EP-001.09
- **Permitted parallelism:** independent of EP-001.03, .04, .05, .12, .13 once EP-001.02 lands

## Intent and outcome

`PropertyAccessPolicy` on `GET /api/properties/{id}` returns `404 Not Found` for an authenticated but non-authorized requester (plan OP-6). The client router preserves the intended URL through the login cycle for unauthenticated deep links and revisits it after a successful login.

## Relevant context and requirements

- Access rule comes from EP-001.03 (User-direct stakeholder OR User-via-Organization stakeholder).
- **Invitation acceptance authorization is a separate concern owned by EP-001.13.** This node does not implement it.
- Some router return-URL machinery lands in EP-001.01; this node ensures its behavior for `/properties/:id`.

## Constraints / established direction

- **404**, not 403, for the non-invitation deep-link on a Property the User cannot access. Do not disclose existence.
- Complies with plan hygiene **H-4** for the JSON error response shape and `Allow` header.

## Expected evidence

- Endpoint tests for {authenticated authorized, authenticated non-authorized, unauthenticated} with the expected outcomes.
- Client-side test demonstrating return-URL preservation and revisit.
- Report at `docs/engineering/agents/reports/EP-001.07-deep-link-authorization-non-invitation.md`.

## Handoff / stop condition

Deep-link authorization is enforced for property URLs. Invitation URL authorization lives entirely in EP-001.13.
