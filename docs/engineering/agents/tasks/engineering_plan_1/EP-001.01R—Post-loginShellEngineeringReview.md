## Review focus

At minimum, independently investigate the following observations.

### 1. Dependency and ownership integrity

EP-001.01 declares EP-001.06 as a dependency for bilingual i18n bundles.

The EP-001.01 implementation report states that the executing Role created the English bundle and modified language detection itself.

Determine:

- whether EP-001.01 absorbed work owned by EP-001.06;
- whether this constitutes a graph/boundary violation or an acceptable prerequisite realization under the applicable contracts;
- what status EP-001.06 should now have;
- whether duplicated or conflicting downstream work could result.

Do not assume a violation merely because files overlap. Judge against the actual task and Role contracts.

### 2. Authentication semantics for `GET /api/properties`

The report states that `RootRedirect` currently treats HTTP 404 or 401 from `GET /api/properties` as equivalent to zero accessible properties and routes to `/welcome`.

Determine whether treating 401 as a Zero Properties state is semantically and operationally correct.

Specifically inspect interaction between:

- `AuthProvider`;
- `RequireAuth`;
- `/api/auth/me`;
- `GET /api/properties`;
- expired/invalid sessions;
- route/error behavior.

Assess whether an authentication failure can be incorrectly presented as a legitimate empty portfolio.

### 3. Sign-out behavior

The report states that no backend logout endpoint exists and the shell's current sign-out behavior redirects to `/login`.

Determine whether the UI presents this as actual sign-out while leaving the authenticated session valid.

Inspect interaction with `PublicOnly`, `AuthProvider`, cookies/session state, and subsequent navigation.

Determine whether this is:

- acceptable placeholder behavior;
- misleading but non-blocking;
- a correctness issue;
- or something that should be removed/disabled until real session invalidation exists.

### 4. Scope and downstream boundary preservation

Inspect for any other implementation that materially enters work assigned to:

- EP-001.02 / Property;
- EP-001.03 / Party and PropertyStakeholder;
- EP-001.04 / Portfolio and Property Home;
- EP-001.06 / bilingual i18n;
- EP-001.12 / Payment;
- EP-001.13 / Invitation domain;
- EP-001.14 / invitation client experience.

Placeholders and integration seams are allowed where required by EP-001.01.

Distinguish preparatory scaffolding from implementation of another node's owned behavior.

### 5. Contract and evidence quality

Verify that the completion claim is supported by evidence appropriate to the task.

Review at least:

- routing behavior;
- return-URL preservation and open-redirect protection;
- ADR-003;
- error handling;
- accessibility requirements;
- build evidence;
- absence or presence of automated verification;
- limitations recorded by the implementing Role.

Do not treat a successful build as sufficient evidence of behavioral correctness.
