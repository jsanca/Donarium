# EP-001.01R2 — Post-login Shell Remediation Re-review

- **Parent work node:** EP-001.01
- **Remediation:** EP-001.01F — Post-login Shell Review Remediation
- **Prior review:** EP-001.01R — Post-login Shell Engineering Review
- **Assigned Role:** `engineering-reviewer`
- **Status:** READY FOR ADOPTION
- **Depends on:** EP-001.01F
- **Review scope:** remediation verification

## Intent and outcome

Independently verify the remediation produced by EP-001.01F against the findings
from EP-001.01R.

This is a focused re-review, not a new general review of EP-001.01.

Determine whether the remediation correctly resolves the findings assigned to
the software-engineer Role without introducing material regressions or expanding
scope.

Do not repair implementation.

## Findings to verify

Verify the disposition of:

- AAR-001 — misleading/non-functional Sign out
- AAR-002 — HTTP 401 interpreted as zero properties
- AAR-004 — ADR-003 AuthProvider contract drift
- AAR-005 — hardcoded-English error/loading states
- AAR-006 — divergent PublicOnly return-URL sanitizer
- AAR-007 — misleading fetchProperties documentation only

AAR-003 remains outside this remediation and must remain OPEN pending
Product Architect / Knowledge Curator reconciliation.

## Required review

Inspect the actual implementation and durable remediation evidence.

Do not accept the remediation report as proof by itself.

Verify at minimum:

1. AAR-001
   - no UI action claims to terminate the authenticated session when it does not;
   - no fake client-side logout behavior was introduced;
   - no backend logout capability was added.

2. AAR-002
   - HTTP 401 from GET /api/properties can no longer produce Zero Properties;
   - authentication failure returns the User to the authentication lifecycle;
   - returnUrl preservation remains safe and correct;
   - the temporary 404 → zero seam remains limited to EP-001.02 compatibility.

3. AAR-004
   - ADR-003 describes the actual AuthProvider/session behavior after remediation.

4. AAR-005
   - previously identified loading/error states consume the existing i18n mechanism;
   - no equivalent hardcoded-English replacement was introduced.

5. AAR-006
   - PublicOnly uses the canonical shared return-URL sanitizer;
   - return-URL/open-redirect protections have not regressed.

6. AAR-007
   - documentation accurately describes where the temporary 404 seam is handled;
   - the seam itself has not been prematurely changed.

Also inspect the remediation diff for regressions directly caused by EP-001.01F.

Do not reopen unrelated aspects of the original implementation unless the
remediation materially affected them.
